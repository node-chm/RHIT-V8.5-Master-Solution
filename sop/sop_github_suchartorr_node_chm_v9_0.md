# SOP: การทำงานและส่งงานบน GitHub (`suchartorr` & `node-chm` | V9.0)

## 1. หลักการและกติกาสำคัญ
- **ศูนย์กลางข้อมูล (SSoT):** ยึด `suchartorr/RHIT-V8.5-Master-Solution` (`main` / V9.0) เป็นหลัก และรักษาฝั่ง `node-chm/main` ให้สะอาดเป็น V9.0 (ไม่มีโฟลเดอร์เก่า `applications/RHIT-SEWN-v2` ค้าง)
- **แจ้งก่อนทำสิ่งที่กระทบ:** ใช้ **GitHub Issue** เป็นศูนย์กลางแจ้งเรื่องที่กระทบกับโครงการและติดตาม **สถานะการตัดสิน** ร่วมกัน ส่วนการแสดงความเห็นตอบกลับเป็นอิสระของแต่ละคน
- **1 เรื่อง = 1 Branch ของแต่ละคน:** แต่ละคนแยกทำทีละเรื่องต่อ 1 Branch ไม่ทำปะปนกันใน Branch เดียว หากผู้ทำคนเดิมทำหลายเรื่องให้แยกหลาย Branch และหากมีอีกคนเข้ามาต้องทำเรื่องที่ไม่ซ้ำกับที่กำลังทำอยู่
- **เส้นทางส่งงาน:** ผู้ปฏิบัติงาน Fork จาก `suchartorr/RHIT-V8.5-Master-Solution` อัปเดตให้ทัน `main` และเมื่อเสร็จงานใน Branch ของตนให้เปิด Pull Request เข้า **`suchartorr:main` โดยตรง** เพื่อให้ทั้ง `suchartorr` และฝั่ง `node-chm` เห็นความเคลื่อนไหวพร้อมกัน
- **การเก็บหรือลบ Branch:** ไม่บังคับให้ลบ Branch หลัง Merge เป็นสิทธิของเจ้าของโฟลเดอร์หรือผู้ทำเองว่าจะเก็บไว้หรือลบออก

## 2. รูปแบบการตั้งชื่อ Branch และโครงสร้างโฟลเดอร์
- **รูปแบบชื่อ Branch (แบบที่ 3):** `ws<เลข>/<ผู้ทำ>-<เรื่อง>` เช่น:
  - `ws1/node-c1-fit`
  - `ws1/node-sewn-check`
  - `ws4/node-model-sync`
  - `ws1/somchai-data-prep` (กรณีมีอีกคนทำเรื่องอื่นที่ไม่ซ้ำ)
- **กติกาการเขียนชื่อ Branch:** ใช้ตัวพิมพ์เล็กทั้งหมด ใช้ขีดกลาง (`-`) คั่นคำ ห้ามเว้นวรรคและห้ามใช้อักขระพิเศษ
- **การจัดวางโฟลเดอร์:**
  - `workstreams/ws1/<หัวข้องานย่อย>/` สำหรับงานใน WS1
  - `workstreams/ws4/<หัวข้องานย่อย>/` สำหรับงานใน WS4 (และ `workstreams/ws<เลข>/` สำหรับ WS ที่ประกาศเพิ่มในอนาคต)
  - แยกโฟลเดอร์ย่อยและชื่อไฟล์ตามขอบเขตงานให้ชัดเจน เพื่อไม่ให้โฟลเดอร์หรือไฟล์ชนและซ้ำกัน

## 3. ขั้นตอนปฏิบัติ
1. **เปิด Issue และเช็กสถานะ:** หากเป็นเรื่องที่กระทบกับภาพรวมหรือต้องการความเห็น/การตัดสินใจร่วมกัน ให้เปิดหรืออัปเดตใน **GitHub Issue** เพื่อดูสถานะการตัดสินและไม่ให้ทำเรื่องซ้ำกับคนอื่น
2. **ซิงก์ต้นทาง:** อัปเดต Fork ของตนเองให้ทัน `suchartorr:main` ก่อนเริ่มทำงาน
3. **สร้าง Branch ตามแบบที่ 3:** แตก Branch ใหม่จาก `main` โดยตั้งชื่อ `ws<เลข>/<ผู้ทำ>-<เรื่อง>` เฉพาะเรื่องนั้นๆ
4. **ทำงานในขอบเขตที่แยกไว้:** แก้ไขหรือเพิ่มไฟล์ในโฟลเดอร์ของงานนั้นให้เรียบร้อย โดยไม่แก้ไฟล์นอกขอบเขตหรือสร้างโฟลเดอร์ซ้ำกัน
5. **อัปเดตอีกครั้งและเปิด PR:** ดึงอัปเดตล่าสุดจาก `suchartorr:main` เข้า Branch ของตนเอง แล้วเปิด Pull Request เข้า **`suchartorr:main` โดยตรง** เมื่อ Merge เสร็จแล้วจะเก็บ Branch ไว้หรือลบทิ้งก็แล้วแต่ผู้ดูแล/ผู้ทำตัดสินใจ
