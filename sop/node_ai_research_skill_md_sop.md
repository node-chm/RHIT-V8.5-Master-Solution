# รายงานและกรอบการมอบหมายงานให้ `node` (`AI_RESEARCH_SKILL.md` & SOP)

## 1. ภาพรวมภารกิจและเหตุผลในการแยกทำ
* **วัตถุประสงค์:** ปรับปรุง `AI_RESEARCH_SKILL.md` และ SOP (`sop_github_suchartorr_node_chm_v9_0.md`) ให้ทำงานสอดคล้องกันได้ดีที่สุด เพื่อให้ AI ผู้ช่วยอธิบายและทำวิจัยตามบทบาทใน `README` สามารถตอบและให้คำแนะนำเรื่องการร่วมงานบน GitHub ได้ชัดเจนเมื่อมีผู้สนใจสอบถาม
* **เหตุผลที่ต้องแยกทำ:** แยกออกมาเป็นงานเฉพาะใน Branch ของตนเอง เพื่อลดการแก้ไฟล์หลักหรือไฟล์ระบบบ่อยเกินไปจนเกิดความเสี่ยงหรือความคลาดเคลื่อน และให้ `node` ทดลองจนมั่นใจก่อนส่งกลับมาอัปเดตเข้า `suchartorr:main`
* **วงจรการทำงานต่อเนื่อง:** เมื่อ `node` ทดลองจนมั่นใจแล้วให้ส่งกลับเข้ามาเพื่อให้ `suchartorr` อัปเดตให้โครงการหลัก และหากอนาคตมีประเด็นที่กระทบหรือเปลี่ยนแปลง ให้ส่งเข้าสู่รอบปรับปรุงและทดสอบซ้ำในลักษณะเดียวกัน

## 2. สิ่งที่มอบให้ `node` วิเคราะห์และนำเสนอทางเลือกให้ตัดสินใจ
เพื่อให้ยืดหยุ่นตามหน้างานจริง ให้ `node` วิเคราะห์และจัดทำทางเลือกมาให้ตัดสินใจในประเด็นเหล่านี้:

* **วิธีเชื่อมโยงระหว่าง `AI_RESEARCH_SKILL.md` กับ SOP:** `node` วิเคราะห์เปรียบเทียบข้อดี-ข้อเสีย แล้วเสนอทางเลือกให้ตัดสินใจ เช่น การดึง/สรุปกติกาสำคัญลงใน Skill โดยตรง vs การอ้างอิงไฟล์ SOP หรือแยกส่วนขยาย เพื่อให้ AI ตอบเรื่อง GitHub ได้ครบถ้วนโดยไม่ทำให้โครงสร้างหลักของ Skill หนาหรือซับซ้อนเกินไป
* **จุดที่ควรปรับปรุงในตัวไฟล์ SOP (`sop_github_suchartorr_node_chm_v9_0.md`):** `node` ตรวจดูว่าเมื่อใช้เป็นคู่มือให้ผู้สนใจเข้ามาศึกษาและร่วมงานได้ด้วย มีจุดใดใน SOP ที่ควรเพิ่มเติมหรือปรับถ้อยคำให้ชัดเจนขึ้น แล้วเสนอเป็นทางเลือกให้พิจารณา
* **รูปแบบการรายงานผลการทดลองก่อนส่งกลับ:** `node` เสนอแนวทางการสรุปผลทดสอบ (เช่น ตัวอย่างคำถาม-คำตอบเรื่องการร่วมงานบน GitHub และจุดตรวจว่าไม่กระทบตัวเลข/กติกา SSOT เดิม) เพื่อให้ตัดสินใจและส่ง PR เข้า `suchartorr:main` ได้อย่างมั่นใจ

## 3. ขั้นตอนการเดินงานของ `node` ตาม SOP
1. **แจ้งใน GitHub Issue:** เปิดหรืออัปเดต Issue เพื่อแจ้งว่า `node` กำลังทำเรื่องปรับปรุง `AI_RESEARCH_SKILL.md` ร่วมกับ SOP และติดตามสถานะการตัดสินใจร่วมกัน
2. **ซิงก์และเปิด Branch ตามแบบที่ 3:** อัปเดต Fork ให้ทัน `suchartorr:main` แล้วแตก Branch เฉพาะเรื่องนี้ (เช่น `ws1/node-ai-skill-sop`)
3. **วิเคราะห์ ทดลอง และเสนอทางเลือก:** ปรับปรุงและทดลองใช้งานจนมั่นใจ พร้อมสรุปทางเลือกที่วิเคราะห์แล้วให้ตัดสินใจ
4. **ส่งกลับเข้าโครงการหลัก:** ดึงอัปเดตล่าสุดจาก `suchartorr:main` เข้า Branch แล้วเปิด Pull Request เข้า `suchartorr:main` โดยตรงเพื่อให้ `suchartorr` อัปเดตให้โครงการหลัก (ส่วนการเก็บหรือลบ Branch ให้เป็นสิทธิของผู้ทำ)
